# 机票预订需求文档

本文档旨在详细描述机票预订流程的核心功能、页面元素、用户交互及系统行为。

0. 首页（导航与路由）

    0.1 用户菜单
        Scenario: 已登录时顶部栏展示用户名入口
            Given 用户已登录且位于首页
            When 首页顶部栏渲染
            Then 展示用户名入口
            And 不展示“登录”按钮与“注册”按钮

        Scenario: 未登录时顶部栏展示登录与注册按钮
            Given 用户未登录且位于首页
            When 首页顶部栏渲染
            Then 展示“登录”按钮与“注册”按钮
            And 不展示用户名入口

        Scenario: 触摸用户名位置展现下拉菜单
            Given 用户已登录且位于首页
            When 用户触摸用户名位置
            Then 展示下拉菜单

        Scenario: 点击下拉菜单中的用户名跳转到“个人中心-我的信息”
            Given 下拉菜单已展开
            When 用户点击菜单中的“用户名”
            Then 跳转至个人中心的“我的信息”页面

        Scenario: 点击下拉菜单中的常用信息跳转到“个人中心-常用旅客信息”
            Given 下拉菜单已展开
            When 用户点击菜单中的“常用信息”
            Then 跳转至个人中心的“常用旅客信息”页面

    0.3 搜索入口
        Scenario: 点击搜索框中的搜索跳转到搜索结果页
            Given 用户已在首页填写完整且合法的搜索条件
            And 用户已登录
            When 用户点击搜索框中的“搜索”
            Then 跳转至搜索结果页面

        Scenario: 用户未登录时点击搜索
            Given 用户已在首页填写完整且合法的搜索条件
            And 用户未登录
            When 用户点击搜索框中的“搜索”
            Then 系统跳转至登录页
            And 登录成功后自动携带原搜索条件跳转至搜索结果页面



1. 航班搜索结果
    1.1 单程搜索结果页
        1.1.1 进入方式：
        - 从首页搜索卡提交“单程”条件后点击搜索进行跳转。
        - 刷新或分享带查询参数的 URL，保留筛选状态并重新加载列表。
        1.1.2 页面元素：
        - “出发地输入框”、“目的地输入框”、“出发日期选择器”。
        - 日期选择横栏：用户可点击横栏中的日期切换出发日期，用蓝色渲染当前选中的日期，默认为今天。
        - 快捷筛选：`航空公司`、`起降时间`、`机场`、`更多`。
        - 快捷排序：“按起飞时间”、“按价格”。
        - 航班卡片：`航空公司名称`、`航班号`、`起飞时间/机场/航站楼`、`到达时间/机场/航站楼`、`最低价`、`订票按钮`。
        - 套餐面板（展开后）：`套餐名称`、`价格`、`退改政策`、`行李额`、`预订按钮`。
        1.1.3 查询保护与稳定性约定（防止频繁查询导致服务不可用）
        - 对“搜索/筛选/分页”触发的数据加载，统一做请求合并与限流：
          - 防抖：输入或筛选变更触发加载时，防抖 300ms，仅以最后一次变更为准。
          - 取消：在新一次加载开始时，取消/忽略前一次未完成的加载结果，避免乱序覆盖。
          - 去重：相同查询条件在短时间内重复触发时不重复加载。
          - 并发：同一页面同一数据源同时仅允许 1 个在途加载任务。
          - 交互：加载中“搜索/重试/分页/筛选”按钮应置灰或展示忙碌态，避免连点。
        - 超时与降级：
          - 单次加载超过 8 秒视为失败，提示“系统繁忙，请稍后重试”，并保留当前筛选条件与已展示结果（如有）。
          - 不做无限自动重试；允许用户手动重试，且连续失败时提示更换条件或稍后再试。

        Scenario: 正常加载并展示航班列表
            Given 用户已登录且访问含有效查询参数的结果页
            When 系统加载本地模拟航班数据并渲染列表
            Then 页面显示航班列表，卡片包含航司、航班号、起降时间与最低价
            And 展开套餐面板可见套餐明细与“预订”按钮

        Scenario: 主页进入搜索内容延续搜索
            Given 用户已登录且位于首页
            And 用户已在搜索框中输入出发地、目的地与出发日期
            When 用户点击搜索框中的“搜索”
            Then 系统跳转至搜索结果页面
            And 页面展示包含用户输入条件的航班列表
            And 顶部的“出发地输入框”、“目的地输入框”、“出发日期选择器”正确显示用户在首页输入的内容

        Scenario: 正常选择套餐并进入订票页
            Given 用户在结果页点击某航班信息卡的“订票”按钮
            Then 展开某航班的套餐面板
            When 用户点击该航班某套餐的“预订”按钮
            Then 系统在本地生成预订草稿并写入会话，要求信息完整（`flightId`、`packageId`、`departDate`、`priceVersion`）
            And 系统保存所选航班与套餐到会话
            And 跳转至 `booking` 页面开始填写信息

        Scenario: 变更查询条件（出发地）
            Given 用户位于航班搜索结果页
            When 用户修改“出发地输入框”并点击“搜索”
            Then 系统应以新的出发地作为查询条件重新加载列表
            And 加载完成后列表应展示新条件对应的航班结果

        Scenario: 变更查询条件（目的地）
            Given 用户位于航班搜索结果页
            When 用户修改“目的地输入框”并点击“搜索”
            Then 系统应以新的目的地作为查询条件重新加载列表
            And 加载完成后列表应展示新条件对应的航班结果

        Scenario: 变更查询条件（出发日期）
            Given 用户位于航班搜索结果页
            When 用户修改“出发日期选择器”并点击“搜索”
            OR 用户点击日期横栏中的其他日期
            Then 系统应以新的出发日期作为查询条件重新加载列表
            And 加载完成后列表应展示新条件对应的航班结果

        Scenario: 使用快捷筛选
            Given 用户位于航班搜索结果页
            When 用户使用快捷筛选中的“航空公司”等筛选器选择某个类型
            Then 系统应以新的筛选条件作为查询参数重新加载列表
            And 加载完成后列表应展示新条件对应的航班结果

        Scenario: 使用快捷排序
            Given 用户位于航班搜索结果页
            When 用户点击快捷排序中的“按起飞时间”或“按价格”
            Then 系统应以新的排序方式重新加载列表
            And 加载完成后列表应按新排序展示航班结果

        Scenario: 输入异常（过去日期）
            Given 查询参数中的 `departDate` 为今天之前
            When 用户访问搜索结果页
            Then 系统提示“不可选择过去日期”
            And 页面保持在本页并允许用户重新选择日期

        Scenario: 状态异常（未登录）
            Given 用户未登录
            When 用户打开搜索结果页或点击“预订”
            Then 系统跳转至登录页
            And 登录成功后回到结果页继续预订流程

        Scenario: 系统异常（搜索数据加载失败）
            Given 用户首次进入结果页
            When 本地模拟航班数据加载失败或解析异常
            Then 页面展示错误提示“搜索失败/网络异常，请稍后重试”
            And 保留筛选条件并提供继续浏览/重试入口

        Scenario: 无可售结果
            Given 查询条件有效但无库存
            When 搜索返回空列表
            Then 页面提示“暂无可售航班”

    1.2 预订入口（套餐面板）
        1.2.1 进入方式：
        - 在航班卡片点击“订票”展开套餐面板；点击某套餐的“预订”按钮进入订票页。
        1.2.2 页面元素：
        - 套餐卡片：`套餐名称`、`价格`、`退改`、`行李额`、`预订按钮`。

        Scenario: 正常选择套餐并进入订票页
            Given 用户在结果页展开某航班的套餐面板
            When 用户点击某套餐的“预订”按钮
            Then 系统保存所选航班与套餐到会话
            And 跳转至订票页开始填写信息

        Scenario: 输入异常（套餐标识缺失）
            Given 用户点击“预订”时套餐 ID 缺失或无效
            When 系统尝试进入订票页
            Then 阻止跳转并提示“套餐信息异常，请重试”
            And 保持在当前结果页


2. 订票页面（乘机人与联系人信息）
    2.1 填写乘机人与联系人
        2.1.1 进入方式：
        - 从结果页套餐的“预订”跳转至订票页。
        2.1.2 页面元素：
        - 乘机人复选框：可选择在常用旅客信息中已保存的乘机人
        - 乘机人信息卡：`姓名输入框`、`证件类型下拉`（身份证/护照等）、`证件号输入框`。
        - 新增乘机人选项：用于新建一个乘机人信息卡
        - 删除选项：用于删除该信息卡
        - 联系人信息：`国家/地区码下拉`、`联系人手机号输入框`。
        - 操作：`下一步`按钮。

        Scenario: 正常填写并校验通过进入下一步
            Given 所有信息卡内乘机人姓名非空且证件号合法
            And 联系人手机号合法
            When 用户点击“下一步”
            Then 系统保存乘机人与联系人信息到会话
            And 跳转至增值服务页

        Scenario: 使用保存的乘机人信息
            Given 用户已在常用旅客信息中保存了乘机人信息
            When 用户在订票页点击乘机人复选框
            Then 系统自动填充该乘机人信息到对应输入框
            And 用户可继续填写其他信息

        Scenario: 新增乘机人信息卡
            When 用户点击新增乘机人选项   
            Then 系统新增一个乘机人信息输入栏
            And 用户可继续填写其他乘机人信息    

        Scenario: 删除乘机人信息卡
            Given 用户已新增一个乘机人信息卡
            When 用户点击该乘机人信息卡的删除选项
            Then 系统删除该乘机人信息卡
            And 用户可继续新增或删除其他乘机人信息卡

        Scenario: 输入异常（证件号格式错误）
            Given 证件类型为“身份证”
            When 用户输入不符合规则的身份证号
            Then 在证件号下方提示“证件号码格式不正确”
            And 阻止进入下一步


3. 增值服务页面
    3.1 选择增值服务
        3.1.1 进入方式：
        - 从订票页点击“下一步”跳转至增值服务页。
        3.1.2 页面元素：
        - 增值服务选项（示例占位）：`行李额升级`、`延误险/取消险`、`值机提醒`。
        - 航班摘要与价格清单。
        - 操作：`下一步`按钮（进入支付）。

        Scenario: 正常选择服务进入支付
            Given 用户在服务页可选/不选任何服务
            When 用户点击“下一步”
            Then 系统生成订单号
            And 系统在本地创建订单并写入共享订单存储（`localStorage` 的 `evoflow_orders`），`productType` 为 `flight`，订单状态为 `pending_payment`
            And 跳转至支付页
            And 已选服务计入价格清单

        Scenario: 系统异常（服务列表加载失败）
            Given 用户进入服务页
            When 服务数据加载失败
            Then 显示加载失败占位并允许继续至支付

4. 支付页面
    4.1 支付下单与倒计时
        4.1.1 进入方式：
        - 从服务页点击“下一步”进入支付页。
        4.1.2 页面元素：
        - 金额摘要与航班信息；`剩余时间倒计时（15:00）`；`支付方式`（已保存银行卡/新卡）。
        - 操作：`支付按钮`（根据所选方式显示文案）。

        Scenario: 正常支付并进入完成页
            Given 用户选择“银行卡支付”
            And 倒计时未到期
            When 用户点击“支付”按钮
            Then 系统直接进入完成页

        Scenario: 状态异常（倒计时到期）
            Given 倒计时归零
            When 用户停留在支付页
            Then 弹窗提示“超出时间，请重新开始订单”
            And 提供“返回首页”入口

5. 完成页（出票成功）
    5.1 出票成功与订单状态更新
        5.1.1 进入方式：
        - 支付成功后跳转。
        5.1.2 页面元素：
        - 订单信息卡：`金额`、`路线`、`起降信息`、`乘机人摘要`、`联系人`、`价格明细`。
        - 操作：`返回首页`。

        Scenario: 正常展示完成页并更新订单状态
            Given 用户已完成支付
            When 系统在共享订单存储中更新该订单状态并写入会话
            Then 将订单状态更新
            And 更新 `订单号/状态/下单时间/总金额`
            And 完成页显示“成功出票”与订单摘要

        Scenario: 状态异常（重复创建防抖）
            Given 完成页副作用可能触发两次
            When 系统检测到创建锁
            Then 跳过重复创建
            And 页面仍显示完成信息

        Scenario: 系统异常（订单更新失败）
            Given 完成页触发订单状态更新
            When 共享订单存储写入失败或发生异常
            Then 页面保持完成展示但提示“订单更新失败，稍后查看订单中心”
            And 不影响已完成的支付与页面 UI


6. 全局购票进度条（Header）
    6.1 进度展示
        6.1.2 页面元素：
        - 阶段：`1 乘机信息`、`2 增值服务`、`3 支付`、`4 完成`；当前阶段高亮，已完成显示“✓”。

        Scenario: 正常更新阶段状态
            Given 会话存储记录 
            When 用户进入对应阶段页面
            Then 顶部进度条高亮当前阶段


        Scenario: 系统异常（会话读取失败）
            Given 用户进入任一阶段
            When 会话读取抛出异常
            Then 进度条保持默认显示且不影响页面交互
