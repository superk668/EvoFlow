# 机票预订需求文档

本文档旨在详细描述机票预订流程的核心功能、页面元素、用户交互及系统行为。

0. 首页（导航与路由）

    0.1 用户菜单
        Scenario: 已登录时顶部栏展示用户名入口
            Given 用户已登录且位于首页
            When 首页顶部栏渲染
            Then 展示用户名入口
            And 不展示“登录”按钮与“注册”按钮

        Scenario: 未登录时顶部栏展示登录与注册按钮
            Given 用户未登录且位于首页
            When 首页顶部栏渲染
            Then 展示“登录”按钮与“注册”按钮
            And 不展示用户名入口

        Scenario: 触摸用户名位置展现下拉菜单
            Given 用户已登录且位于首页
            When 用户触摸用户名位置
            Then 展示下拉菜单

        Scenario: 点击下拉菜单中的用户名跳转到“个人中心-我的信息”
            Given 下拉菜单已展开
            When 用户点击菜单中的“用户名”
            Then 跳转至个人中心的“我的信息”页面

        Scenario: 点击下拉菜单中的常用信息跳转到“个人中心-常用旅客信息”
            Given 下拉菜单已展开
            When 用户点击菜单中的“常用信息”
            Then 跳转至个人中心的“常用旅客信息”页面

    0.2 订单入口
        Scenario: 点击我的订单跳转到个人订单中心
            Given 用户已登录且位于首页
            When 用户点击“我的订单”
            Then 跳转至个人订单中心

    0.3 搜索入口
        Scenario: 点击搜索框中的搜索跳转到搜索结果页
            Given 用户已在首页填写完整且合法的搜索条件
            And 用户已登录
            When 用户点击搜索框中的“搜索”
            Then 跳转至搜索结果页面

        Scenario: 用户未登录时点击搜索
            Given 用户已在首页填写完整且合法的搜索条件
            And 用户未登录
            When 用户点击搜索框中的“搜索”
            Then 系统跳转至登录页
            And 登录成功后自动携带原搜索条件跳转至搜索结果页面



1. 航班搜索结果
    1.1 单程搜索结果页
        1.1.1 进入方式：
        - 从首页搜索卡提交“单程”条件后点击搜索进行跳转。
        - 刷新或分享带查询参数的 URL，保留筛选状态并重新加载列表。
        1.1.2 页面元素：
        - “出发地输入框”、“目的地输入框”、“出发日期选择器”。
        - 快捷筛选：`航空公司`、`起降时间`、`机型`、`舱位`、`更多`。
        - 航班卡片：`航空公司名称`、`航班号`、`起飞时间/机场/航站楼`、`到达时间/机场/航站楼`、`最低价`、`订票按钮`。
        - 套餐面板（展开后）：`套餐名称`、`价格`、`退改政策`、`行李额`、`预订按钮`。
        - 采用半硬编码方式展示航班信息。
        1.1.3 查询保护与稳定性约定（防止频繁查询导致服务不可用）
        - 对“搜索/筛选/分页”触发的数据加载，统一做请求合并与限流：
          - 防抖：输入或筛选变更触发加载时，防抖 300ms，仅以最后一次变更为准。
          - 取消：在新一次加载开始时，取消/忽略前一次未完成的加载结果，避免乱序覆盖。
          - 去重：相同查询条件在短时间内重复触发时不重复加载。
          - 并发：同一页面同一数据源同时仅允许 1 个在途加载任务。
          - 交互：加载中“搜索/重试/分页/筛选”按钮应置灰或展示忙碌态，避免连点。
        - 超时与降级：
          - 单次加载超过 8 秒视为失败，提示“系统繁忙，请稍后重试”，并保留当前筛选条件与已展示结果（如有）。
          - 不做无限自动重试；允许用户手动重试，且连续失败时提示更换条件或稍后再试。

        Scenario: 正常加载并展示航班列表
            Given 用户已登录且访问含有效查询参数的结果页
            When 系统加载本地模拟航班数据并渲染列表
            Then 页面显示航班列表，卡片包含航司、航班号、起降时间与最低价
            And 展开套餐面板可见套餐明细与“预订”按钮

        Scenario: 变更查询条件（出发地）
            Given 用户位于航班搜索结果页
            When 用户修改“出发地输入框”并点击“搜索”
            Then 系统应以新的出发地作为查询条件重新加载列表
            And 加载完成后列表应展示新条件对应的航班结果

        Scenario: 变更查询条件（目的地）
            Given 用户位于航班搜索结果页
            When 用户修改“目的地输入框”并点击“搜索”
            Then 系统应以新的目的地作为查询条件重新加载列表
            And 加载完成后列表应展示新条件对应的航班结果

        Scenario: 变更查询条件（出发日期）
            Given 用户位于航班搜索结果页
            When 用户修改“出发日期选择器”并点击“搜索”
            Then 系统应以新的出发日期作为查询条件重新加载列表
            And 加载完成后列表应展示新条件对应的航班结果


        Scenario: 输入异常（过去日期）
            Given 查询参数中的 `departDate` 为今天之前
            When 用户访问搜索结果页
            Then 系统提示“不可选择过去日期”
            And 页面保持在本页并允许用户重新选择日期

        Scenario: 状态异常（未登录）
            Given 用户未登录
            When 用户打开搜索结果页或点击“预订”
            Then 系统跳转至登录页
            And 登录成功后回到结果页继续预订流程

        Scenario: 正常选择套餐并进入订票页
            Given 用户在结果页展开某航班的套餐面板
            When 用户点击某套餐的“预订”按钮
            Then 系统在本地生成预订草稿并写入会话（`sessionStorage` 的 `bookingDraft`），要求信息完整（`flightId`、`packageId`、`departDate`、`priceVersion`）
            And 系统保存所选航班与套餐到会话
            And 跳转至 `booking` 页面开始填写信息

        Scenario: 系统异常（搜索数据加载失败）
            Given 用户首次进入结果页
            When 本地模拟航班数据加载失败或解析异常
            Then 页面展示错误提示“搜索失败/网络异常，请稍后重试”
            And 保留筛选条件并提供继续浏览/重试入口

        Scenario: 状态异常（无可售结果）
            Given 查询条件有效但无库存
            When 搜索返回空列表
            Then 页面提示“暂无可售航班”并建议更换筛选条件

    1.2 预订入口（套餐面板）
        1.2.1 进入方式：
        - 在航班卡片点击“订票”展开套餐面板；点击某套餐的“预订”按钮进入订票页。
        1.2.2 页面元素：
        - 套餐卡片：`套餐名称`、`价格`、`退改`、`行李额`、`预订按钮`。

        Scenario: 正常选择套餐并进入订票页
            Given 用户在结果页展开某航班的套餐面板
            When 用户点击某套餐的“预订”按钮
            Then 系统保存所选航班与套餐到会话
            And 跳转至 `booking` 页面开始填写信息

        Scenario: 输入异常（套餐标识缺失）
            Given 用户点击“预订”时套餐 ID 缺失或无效
            When 系统尝试进入订票页
            Then 阻止跳转并提示“套餐信息异常，请重试”
            And 保持在当前结果页

        Scenario: 状态异常（价格变动）
            Given 用户停留超过5分钟后点击“预订”
            When 系统检测到价格已更新
            Then 显示价格变更提示并要求用户确认
            And 用户确认后进入订票页，金额按最新价格计算

2. 订票页面（乘机人与联系人信息）
    2.1 填写乘机人与联系人
        2.1.1 进入方式：
        - 从结果页套餐的“预订”跳转至 `/booking` 开始填写信息（允许携带查询参数用于恢复页面状态，但不强制）。
        - 航班/套餐等“选购信息”的单一数据源为 `sessionStorage.bookingDraft`（在结果页点击“预订”时写入）。
        2.1.2 页面元素：
        - 乘机人信息：`姓名输入框`、`证件类型下拉`（身份证/护照等）、`证件号输入框`、`国家/地区码下拉`、`乘机人手机（选填）`。
        - 联系人信息：`国家/地区码下拉`、`联系人手机号输入框`。
        - 操作：`下一步`按钮。

        2.1.3 会话草稿结构与一致性约定（用于避免“订票与支付乘机人信息不一致”）
        - 会话键名：`sessionStorage.bookingDraft`
        - 订票页写入字段（字段名必须一致，后续页面不得自造同义字段）：
          - `passenger`：`name`、`idType`、`idNumber`、`phoneNumber`（可为空）
          - `contact`：`phoneNumber`
        - 单一数据源：支付页、完成页、订单落盘时的“乘机人/联系人摘要”必须从 `bookingDraft.passenger` 与 `bookingDraft.contact` 读取或拷贝快照，不允许使用静态占位或其他缓存覆盖。
        - 写入时机：订票页点击“下一步”且校验通过后，必须将当前表单值写入 `bookingDraft`；后续页面不得自行生成或改写乘机人与联系人信息。
        - 读取与校验：进入增值服务页/支付页/完成页时，必须先读取 `bookingDraft` 并校验关键字段存在（`passenger.name`、`passenger.idType`、`passenger.idNumber`、`contact.phoneNumber`）；缺失或解析失败视为会话异常，按各页面“状态异常（草稿缺失）”处理。
        - 展示与脱敏：除订票页输入框外，其他页面（增值服务/支付/完成/订单中心）展示证件号与手机号必须使用脱敏值；订单落盘 `details` 仅保存脱敏后的摘要字段。
        - 禁止硬编码：增值服务页、支付页、完成页不得使用静态姓名/证件号/手机号占位来渲染或调试“乘机人信息摘要”，必须来自 `bookingDraft` 或其快照。

        2.1.4 兼容现有 UI 结构的传递方式（不改变页面布局）
        - 本文档中的“页面元素”描述的是业务字段与交互能力，不强制要求改变现有 UI 的布局层级、卡片结构或信息排版。
        - 为保持现有 UI 结构，乘机人/联系人信息不要求通过 URL Query 传递（且禁止在 URL 中明文携带证件号/手机号）；后续页面只需要从 `sessionStorage.bookingDraft` 读取并在现有摘要区域展示（脱敏）。
        - 若现有页面没有独立摘要区域：至少应确保落盘到 `localStorage.evoflow_orders[*].details.passenger/contact` 的快照来自 `bookingDraft` 且已脱敏。
        - 任一页面读取不到 `bookingDraft`：按该页面“状态异常（草稿缺失）”处理并阻止继续推进流程。

        Scenario: 正常填写并校验通过进入下一步
            Given 乘机人姓名非空且证件号合法
            And 联系人手机号合法
            When 用户点击“下一步”
            Then 系统保存乘机人与联系人信息到会话
            And 跳转至 `booking/services` 增值服务页

        Scenario: 输入异常（证件号格式错误）
            Given 证件类型为“身份证”
            When 用户输入不符合规则的身份证号
            Then 在证件号下方提示“证件号码格式不正确”
            And 阻止进入下一步

        Scenario: 输入异常（联系人手机号非法）
            Given 联系人国家/地区码为“中国 86”
            When 用户输入非 11 位合法手机号
            Then 在手机号输入框下方提示“联系人手机号格式不正确”
            And 阻止进入下一步

        Scenario: 系统异常（会话持久化失败）
            Given 用户点击“下一步”
            When 会话存储写入失败
            Then 页面提示“网络异常，请稍后重试”
            And 保留用户已填写的数据

3. 增值服务页面
    3.1 选择增值服务
        3.1.1 进入方式：
        - 从订票页点击“下一步”跳转至 `booking/services`。
        3.1.2 页面元素：
        - 增值服务选项（示例占位）：`行李额升级`、`延误险/取消险`、`值机提醒`。
        - 航班摘要与价格清单。
        - 乘机人/联系人摘要：展示乘机人姓名、证件类型与证件号脱敏、联系人手机号脱敏；必须从 `sessionStorage.bookingDraft` 读取且与订票页输入一致。
        - 操作：`下一步`按钮（进入支付）。

        Scenario: 正常选择服务进入支付
            Given 用户在服务页可选/不选任何服务
            When 用户点击“下一步”
            Then 系统生成订单号
            And 系统在本地创建订单并写入共享订单存储（`localStorage` 的 `evoflow_orders`），`productType` 为 `flight`，订单状态为 `pending_payment`
            And 订单必须携带用于订单中心展示的快照信息 `details`（至少包含路线、乘机人、联系人与价格明细）
            And `details.passenger` 与 `details.contact` 必须从 `sessionStorage.bookingDraft` 中已保存的数据生成（其中证件号与手机号需脱敏后落盘）
            And 跳转至 `booking/payment/:orderId` 支付页
            And 已选服务计入价格清单

        Scenario: 状态异常（服务不可用）
            Given 某服务临时下线
            When 用户尝试勾选该服务
            Then 显示“服务暂不可用”并自动取消勾选

        Scenario: 系统异常（服务列表加载失败）
            Given 用户进入服务页
            When 服务数据加载失败
            Then 显示加载失败占位并允许继续至支付

        Scenario: 信息一致性（服务页乘机人摘要）
            Given 用户已在订票页填写乘机人姓名与证件号并进入服务页
            When 服务页渲染完成
            Then 服务页展示的乘机人姓名与证件号（脱敏）应与订票页输入一致

        Scenario: 状态异常（草稿缺失）
            Given 用户进入服务页
            When 会话中不存在 `sessionStorage.bookingDraft` 或解析失败
            Then 提示“订单信息异常，请返回重新填写”
            And 提供返回订票页入口
            And 禁止进入支付页

4. 支付页面
    4.1 支付下单与倒计时
        4.1.1 进入方式：
        - 从服务页点击“下一步”进入 `booking/payment/:orderId`。
        4.1.2 页面元素：
        - 金额摘要与航班信息；`剩余时间倒计时（15:00）`；`支付方式`（已保存银行卡/新卡）。
        - 操作：`支付按钮`（根据所选方式显示文案）。
        - 乘机人信息摘要：展示乘机人姓名与证件类型（身份证）及证件号脱敏；必须与订票页已填写并保存的内容一致，且必须从 `sessionStorage.bookingDraft` 读取。
        - 脱敏规则：
          - 联系人手机号：保留前三位与后四位，中间以 `*` 替换
          - 身份证号：保留前三位与后两位，中间以 `*` 替换



        Scenario: 正常支付并进入完成页
            Given 用户选择“银行卡支付”或“新卡支付”
            And 倒计时未到期
            When 用户点击“支付”按钮
            Then 系统直接进入 `booking/complete` 完成页

        Scenario: 信息一致性（乘机人与身份证信息）
            Given 用户已在订票页填写乘机人姓名与身份证号并进入支付页
            When 支付页渲染完成
            Then 支付页展示的乘机人姓名与身份证号（脱敏）应与订票页输入一致

        Scenario: 状态异常（乘机人信息缺失或不一致）
            Given 支付页读取不到乘机人/身份证信息或信息不一致
            When 支付页渲染
            Then 提示“乘机人信息异常，请返回重新填写”
            And 提供返回订票页入口
            And 禁止发起支付

        Scenario: 输入异常（新卡信息不完整）
            Given 用户选择“使用新卡支付”
            When 卡号/姓名/有效期/CVV 为空或格式错误
            Then 支付按钮保持不可用或提示“请填写完整且有效的卡信息”
            And 阻止进入完成页

        Scenario: 状态异常（倒计时到期）
            Given 倒计时归零
            When 用户停留在支付页
            Then 弹窗提示“超出时间，请重新开始订单”
            And 提供“返回首页”入口

        Scenario: 系统异常（支付请求失败）
            Given 用户点击“支付”
            When 系统模拟支付失败或发生异常
            Then 提示“支付失败，请稍后重试”
            And 保留支付页状态与输入数据

5. 完成页（出票成功）
    5.1 出票成功与订单状态更新
        5.1.1 进入方式：
        - 支付成功后跳转至 `booking/complete`。
        5.1.2 页面元素：
        - 订单信息卡（保持现有 UI 结构）：`金额`、`路线`、`起降信息`、`乘机人摘要`、`联系人`、`价格明细` 可按现有布局选择展示项，但“乘机人/联系人摘要”的来源与脱敏规则必须满足。
        - 乘机人/联系人摘要：优先展示订单快照 `details.passenger` 与 `details.contact`（均为脱敏值）；若仅能读取到 `bookingDraft`，则以其生成脱敏摘要展示，但不得展示证件号与手机号原文。
        - 操作：`返回首页`。

        Scenario: 正常展示完成页并更新订单状态
            Given 用户已完成支付
            When 系统在共享订单存储中更新该订单状态并写入会话
            Then 将订单状态更新为 `pending_travel`
            And 更新 `订单号/状态/下单时间/总金额`
            And 完成页显示“成功出票”与订单摘要

        Scenario: 状态异常（重复创建防抖）
            Given 完成页副作用可能触发两次
            When 系统检测到创建锁或已有 `createdOrderId`
            Then 跳过重复创建
            And 页面仍显示完成信息

        Scenario: 系统异常（订单更新失败）
            Given 完成页触发订单状态更新
            When 共享订单存储写入失败或发生异常
            Then 页面保持完成展示但提示“订单更新失败，稍后查看订单中心”
            And 不影响已完成的支付与页面 UI

        Scenario: 信息一致性（完成页乘机人摘要）
            Given 用户已完成支付并进入完成页
            When 完成页渲染完成
            Then 完成页展示的乘机人姓名与证件号（脱敏）应与订票页输入一致


6. 全局购票进度条（Header）
    6.1 进度展示
        6.1.1 进入方式：
        - 在 `/booking/*` 路由展示进度条。
        6.1.2 页面元素：
        - 阶段：`1 乘机信息`、`2 增值服务`、`3 支付`、`4 完成`；当前阶段高亮，已完成显示“✓”。

        Scenario: 正常更新阶段状态
            Given 会话存储记录 `bookingStage`
            When 用户进入对应阶段页面
            Then 顶部进度条高亮当前阶段

        Scenario: 状态异常（阶段信息缺失）
            Given `bookingStage` 未写入或非法
            When 用户进入任一阶段
            Then 默认回退为第 1 阶段展示

        Scenario: 系统异常（会话读取失败）
            Given 用户进入任一阶段
            When 会话读取抛出异常
            Then 进度条保持默认显示且不影响页面交互


7. 路由与前端约定
    - 航班搜索结果页：`/flights/list`
    - 订票页（乘机人与联系人）：`/booking`
    - 增值服务页：`/booking/services`
    - 支付页：`/booking/payment/:orderId`
    - 完成页：`/booking/complete`
    - 进度条展示范围：`/booking/*`
    - 文档内出现的 `booking/...` 视为 `/booking/...`
    - 本地共享订单存储约定：
      - 存储位置：`localStorage`
      - 键名：`evoflow_orders`
      - 数据结构：JSON 数组
      - 最低字段：`orderId`、`productType`、`status`、`createdAt`、`departAt`、`totalAmount`、`details`
      - `details` 最低字段：
        - `route`：`fromCity`、`toCity`
        - `passenger`：`name`、`idType`、`idNumberMasked`
        - `contact`：`phoneNumberMasked`
        - `priceItems`：数组（项目名、单价、数量）
    - 会话草稿约定：
      - 存储位置：`sessionStorage`
      - 键名：`bookingDraft`
    - UI 结构保持现有实现为准；本文件重点约束“路由、字段来源、校验、脱敏与本地存储结构”，不强制要求按示例重排 UI。
